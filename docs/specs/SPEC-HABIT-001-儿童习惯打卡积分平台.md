## 二、问题与用户价值

家长希望通过一台家庭平板，帮助十二岁的果果和三岁多的阳阳共同养成学习与生活习惯。两个孩子年龄和理解能力差异较大，需要各自的任务池、打卡目标、积分和反馈风格，同时又要让孩子操作足够简单，让家长保留最终核实、清算和纠错能力。[来源：D-001、D-002]

第一版的价值是把日常行为转化为孩子可理解的目标进度：孩子完成任务并打卡，家长每天共同核实和清算，积分推进目标及虚拟养成活动，连续完成获得递增奖励，未完成按规则不得分或扣分。[来源：D-001、D-003]

系统主要在单台 MatePad 上运行，应在无网络时完成全部核心流程，不要求家庭维护服务器。真实家庭数据必须能够导出、恢复和随版本升级迁移。[来源：ADR-0002、R-001]

## 三、范围

### 3.1 第一版包含

- 固定的果果和阳阳两个孩子账套。
- 孩子端免密码入口及账套切换。
- 一个受密码保护的家长端。
- 幼儿园和初中两个年龄阶段的内置任务模板。
- 每个孩子独立的任务池任务及任务默认配置。
- 同一孩子同时进行多个独立打卡目标。
- 按星期指定日期和按自然周累计次数的任务计划。
- 孩子和家长提交打卡，孩子撤销未清算打卡。
- 按日期和按周期的任务豁免。
- 完成积分、未完成不得分或扣分、任务连续奖励及上限。
- 家长预览、修正并确认每日清算。
- 撤销清算、重新清算和清算修订历史。
- 目标达成、提前终止、受控恢复和只读目标历史。
- 每个目标一个内置虚拟养成活动。
- 按孩子差异化的老师反馈、鼓励动画、惩罚动画和适量音效。
- 本地关系型数据存储、模式迁移、JSON 导入导出。
- 横屏、竖屏和分屏的 MatePad 界面适配。

### 3.2 第一版不包含

- 新增或删除孩子。
- 多家长协作、权限分级或远程账号。
- 手机、电脑、iOS、Android、网页或桌面客户端。
- 服务端、云数据库、局域网服务器、多设备同步或冲突合并。
- 社交分享、家庭排行榜、支付或实物奖励兑现跟踪。
- 推送通知、语音朗读或自动语音老师。
- 家长上传或制作主题、老师形象、动物、植物、成长阶段或动画。
- 睡觉时间自动判断、分档积分或提前睡觉额外奖励。
- 游戏引擎、三维动画、视频动画管线。
- 应用市场公开发布流程；家庭自用先通过签名调试包安装。
- 产品评价收集和业务成功指标统计。

## 用户故事

1. 作为家长，我希望在一个应用中管理果果和阳阳，同时保持两人的任务、目标和积分独立。
2. 作为孩子，我希望免密码进入自己的页面，快速看到今天可以完成的任务。
3. 作为孩子，我希望清楚知道当前正在操作哪个孩子账套，避免替另一名孩子误打卡。
4. 作为家长，我希望从适龄任务模板快速建立任务池，并能按孩子实际情况修改任务。
5. 作为家长，我希望为同一孩子同时设置多个目标，让学习和生活习惯可以并行培养。
6. 作为家长，我希望每个目标独立设置门槛、奖励、计划时长和虚拟养成活动，让孩子理解努力方向。
7. 作为家长，我希望任务既能安排在指定星期，也能设置每周完成若干次，以适应不同习惯。
8. 作为孩子，我希望一次实际完成只需打卡一次，即使该任务同时用于多个目标。
9. 作为孩子，我希望频率任务同一天完成多次时可以逐次记录并累计进度。
10. 作为孩子，我希望在清算前撤销误打卡，不必让家长重做整个清算。
11. 作为家长，我希望能够代孩子打卡、修正未清算记录并处理特殊情况豁免。
12. 作为家长，我希望确认前看到完整清算预览，核对奖励、扣分和目标进度。
13. 作为家长，我希望一次确认完成孩子当天所有目标的清算，避免遗漏或部分入账。
14. 作为孩子，我希望通过老师说明、鼓励和虚拟成长理解当天获得的积分。
15. 作为孩子，我希望发生扣分时看到明确说明和一次惩罚反馈，理解未完成的后果。
16. 作为家长，我希望发现历史错误后可以撤销清算、修正并重新清算，同时保留修订记录。
17. 作为家长，我希望目标提前达成或超过计划时长时，系统按既定规则自动处理。
18. 作为家长，我希望能够终止不再适合的目标，并保留只读历史。
19. 作为家长，我希望在没有网络时仍能完成打卡、清算和管理。
20. 作为家长，我希望导出并恢复完整家庭数据，避免卸载、升级或设备故障造成永久丢失。

### 5.2 关系约束

- 一个孩子账套拥有一个任务池和多个打卡目标。
- 一个任务池任务只属于一个孩子，但可被该孩子的多个目标任务引用。
- 一个目标只属于一个孩子，至少有一个目标任务，并且恰好关联一个虚拟养成活动。
- 一个目标任务只属于一个目标，并引用同一孩子的任务池任务。
- 一条打卡记录属于一个孩子和一个任务池任务，可以被多个目标任务按各自计划解释。
- 一次每日清算属于一个孩子和一个业务日期，覆盖该日期涉及的全部进行中目标。

### 5.3 权威数据

ArkData 本地关系型数据库是业务数据的唯一权威来源。界面状态、动画播放状态和 Preferences 不得充当目标积分、连续记录、清算状态或目标状态的权威记录。Preferences 只保存音效开关、界面偏好和上次选择孩子等少量设备设置。[来源：ADR-0002、R-001]

## 六、主流程

### 6.1 首次使用

1. 应用创建果果和阳阳两个固定孩子账套。
2. 家长设置本地家长密码。
3. 系统按孩子年龄阶段提供适合的默认主题、老师形象和任务模板。
4. 家长可以修改昵称、头像、主题和老师形象。
5. 家长从任务模板复制任务，或直接创建任务池任务。

### 6.2 创建打卡目标

1. 家长选择一个孩子账套。
2. 输入目标名称、描述、目标积分门槛、计划时长和目标奖励。
3. 从该孩子的任务池中选择至少一个任务池任务。
4. 为每个目标任务确认完成积分、未完成规则、扣分值、连续奖励开关、连续奖励上限和任务计划。
5. 选择一个内置虚拟养成活动。
6. 保存后目标立即进入进行中状态，不支持未来开始日期。

### 6.3 孩子打卡

1. 孩子进入自己的入口或切换到自己的孩子账套。
2. 系统展示当前业务日期可执行的按日期任务，以及尚未结束的频率任务周期进度。
3. 孩子每完成一次实际活动，提交一条打卡记录。
4. 同一打卡记录由引用该任务池任务的多个目标任务共享解释。
5. 频率任务允许同一天提交多条有效记录；达到要求次数后不再重复计分，但超额记录可以保留。
6. 孩子发现误操作时，可以在相关日期清算前撤销对应记录。

### 6.4 家长代操作与豁免

1. 家长可以代孩子提交、撤销或修正未清算打卡记录。
2. 对按日期安排的任务，家长可以豁免特定业务日期的一项任务，也可以一次豁免该孩子当天全部按日期任务。
3. 对频率任务，家长按整个任务周期豁免。
4. 豁免结果不奖不扣，也不推进或中断连续记录。

### 6.5 每日清算

1. 家长选择孩子和业务日期并发起清算审阅。
2. 系统汇总打卡、豁免、任务计划和当时有效的目标任务规则。
3. 当天应完成但没有有效打卡或豁免的按日期任务预览为未完成。
4. 频率任务达到次数时，在最后一条达标记录的业务日期预览为已完成；周期结束仍未达标时，在周期最后一天预览为未完成。
5. 家长核对并修正任务状态。
6. 系统按目标分别预览完成积分、连续奖励、扣分、净变化、累计积分和虚拟成长变化。
7. 家长确认后，所有目标清算结果在一个事务中共同生效。
8. 系统按目标逐一播放老师反馈，顺序为奖励说明及一次鼓励、扣分说明及一次惩罚、净变化和累计进度。

### 6.6 清算纠错

1. 家长选择一个已清算业务日期并撤销清算。
2. 原清算版本失效但保留为清算修订记录。
3. 系统按业务日期顺序重算受影响日期及其后的积分、连续记录、历史最高积分和目标状态。
4. 家长修正打卡或任务结果后重新清算。
5. 孩子只查看当前有效结果，家长可以查看全部修订历史。

### 6.7 目标结束

- 清算使目标积分达到门槛时，目标立即变为已达成并停止后续任务要求和计分。
- 家长降低进行中目标的积分门槛且新门槛不高于当前积分时，目标立即变为已达成。
- 家长可以在达成前主动终止目标。
- 已达成和已终止目标进入只读目标历史。
- 撤销清算使已达成目标积分低于门槛时，目标恢复为进行中，并按修正后的事实恢复任务要求和连续记录。

### 6.8 数据备份与恢复

1. 家长从家长端导出完整、版本化的 JSON 备份。
2. 系统通过文件选择器将备份保存到家长选择的位置。
3. 恢复时先读取并检查格式版本、完整性和领域不变量。
4. 检查通过后先保护当前数据，再在一个事务中替换数据。
5. 取消文件选择、文件损坏、版本不兼容或恢复失败时，现有数据保持不变。

## 七、业务规则

### 7.1 任务模板与任务池

- 第一版只内置幼儿园和初中任务模板。
- 初中模板至少包含数学课外练习、英语课外练习、语文阅读、刷牙和目标时间前准备睡觉。
- 幼儿园模板至少包含英语打卡、刷牙、在幼儿园吃早餐、在幼儿园吃午餐和目标时间前准备睡觉。
- 其他通用模板可以按年龄阶段补充，但不得引入不同于本规格的计分模型。
- 模板复制到孩子账套后成为独立任务池任务，可以修改且不再跟随模板变化。
- 任务池任务包含默认完成积分、未完成处理方式、扣分值、连续奖励开关和连续奖励上限。
- 已被目标引用的任务池任务不得物理删除，只能停用。
- 停用任务继续保留在已有目标和历史数据中，但不能加入新目标。
- 完成积分、扣分值、连续奖励上限和目标积分门槛均使用整数；完成积分和门槛必须大于零，扣分值与连续奖励上限不得为负数。

### 7.2 目标任务规则快照

- 任务池任务加入目标时复制当时的任务默认配置。
- 家长可以在目标内覆盖完成积分、未完成处理、扣分值、连续奖励开关、连续奖励上限和任务计划。
- 目标任务保存独立规则快照。
- 任务默认配置后续变化不影响已有目标任务。
- 进行中目标的规则变化只影响尚未清算的日期或周期结果；已清算结果保留当时规则。

### 7.3 按日期任务

- 任务计划可以指定每周一个或多个星期几，例如周一、周三和周五。
- 未安排日期不要求完成，也不中断连续记录。
- 一个目标任务在一个业务日期最多产生一次已完成结果；同日多条打卡不会重复计分。
- 没有有效打卡且没有豁免时，在该业务日期清算中按未完成处理。

### 7.4 频率任务

- 频率任务在任务周期内累计有效打卡次数。
- 第一版的频率周期只支持自然周，每周固定为周一至周日。
- 同一天的多条有效打卡都计入周期进度，不要求发生在不同日期。
- 达到要求次数时，以最后一次达标记录的业务日期产生一次已完成结果并等待该日清算计分。
- 达标前的记录不单独计分。
- 达标后的超额记录可以保留，但不重复计分或增加连续奖励。
- 周期结束仍未达标时，以周期最后一天产生一次未完成结果。
- 周期任务连续奖励按连续完成周期数计算。

### 7.5 完成、未完成与扣分

- 已完成结果获得目标任务的完成积分。
- 未完成结果按目标任务规则不得分或扣一次指定积分。
- 已豁免结果不奖不扣。
- 睡觉任务按普通二元任务处理，由孩子据实勾选并由家长核实；目标时间前准备睡觉视为完成，否则未完成且不得分。
- 睡觉目标时间通过任务名称或描述表达，不增加结构化时间规则。
- 睡觉任务不使用点击时间自动判断，不分档，也不扣分。

### 7.6 连续奖励

- 每个目标任务独立决定是否启用连续奖励。
- 未启用时不维护可计分的连续奖励。
- 首个连续完成结果只获得完成积分，额外连续奖励为零。
- 第二个连续完成结果额外加一分，之后每个连续结果再增加一分。
- 连续奖励上限只限制额外积分，不包含完成积分。
- 未设置上限表示额外奖励不设上限。
- 未完成中断连续记录；下一次完成从额外零分重新开始。
- 未安排日期和豁免不推进也不中断连续记录。
- 同一任务池任务在不同目标中的连续记录互不共享。

### 7.7 目标积分与达成

- 各目标独立积攒目标积分，不存在孩子总积分钱包。
- 每次清算先按目标合计全部奖励和扣分，得到净变化，再更新目标积分。
- 目标积分最低为零，不产生负数。
- 达到门槛时保留超额积分，不截断为门槛值。
- 历史最高积分只增不减。
- 目标到达计划时长仍未达成时继续进行，直到达成或由家长终止。

### 7.8 虚拟成长与反馈

- 每个目标必须且只能关联一个内置虚拟养成活动。
- 虚拟成长进度根据历史最高积分计算，不因扣分倒退。
- 当前积分低于历史最高积分时，后续积分先恢复差额；超过历史最高积分后才继续成长。
- 一个目标清算结果存在至少一项正积分时，奖励说明后最多播放一次鼓励动画。
- 存在至少一项扣分时，扣分说明后播放一次惩罚动画，与净变化正负无关。
- 同时存在奖励和扣分时，先奖励反馈，再扣分反馈，最后展示净变化和累计进度。
- 果果使用偏成熟、克制的主题、老师形象和表达；阳阳使用偏童趣、图形化的表现。

## 八、状态与生命周期

### 8.1 打卡目标

| 当前状态 | 触发 | 新状态 |
| --- | --- | --- |
| 不存在 | 家长创建有效目标 | 进行中 |
| 进行中 | 积分达到门槛或门槛降低至当前积分 | 已达成 |
| 进行中 | 家长主动终止 | 已终止 |
| 已达成 | 撤销清算后重算积分低于门槛 | 进行中 |

已终止目标不通过普通编辑恢复。已达成和已终止目标均只读；只有撤销清算引起的受控重算可以改变已达成状态。[来源：D-002、D-003]

### 8.2 打卡记录

- 提交后为有效记录。
- 清算前可以撤销，撤销事实保留可追溯信息。
- 清算后孩子和家长均不能直接修改；家长必须先撤销相关清算。
- 一次实际完成对应一条记录；频率任务允许同日多条不同实际完成记录。

### 8.3 清算

- 清算审阅是只读预览，不改变领域数据。
- 家长确认后成为当前有效版本。
- 撤销后原版本失效但不删除。
- 重新确认生成新版本，旧版本保留在修订历史中。
- 同一孩子同一业务日期只能有一个当前有效清算版本。

## 九、Module 与 Interface

### 9.1 家庭习惯 Module

第一版采用单一深 Module。它拥有全部领域数据和领域行为，并通过三个公共 Interface 入口向 ArkUI 暴露能力。[来源：ADR-0001、D-004]

| 入口 | 责任 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| openSession | 创建孩子或家长会话并确定权限 | 入口类型、孩子标识或家长密码 | 不透明会话、角色、当前孩子 |
| execute | 执行一个完整领域意图并维护全部不变量 | 会话、类型化命令、业务日期、可选预期修订号 | 命令结果、领域事件、最新修订号、可选清算回执 |
| inspect | 读取面向场景的只读快照 | 会话、类型化查询、显式业务日期 | 孩子今日、目标进度、任务池、清算审阅、历史或备份快照 |

### 9.2 execute 命令范围

- 配置孩子资料。
- 从模板添加或直接创建任务池任务。
- 修改或停用任务池任务。
- 创建、修改或终止打卡目标。
- 提交或撤销打卡。
- 按日期豁免任务或豁免频率任务周期。
- 确认或撤销每日清算。
- 设置或验证家长密码。
- 导入已经检查通过的完整备份。

每条命令必须自行完成读取、校验、计算和保存。调用方不得依赖多个命令的特定组合来维持积分、连续记录或目标状态的一致性。

### 9.3 inspect 查询范围

- 孩子当日视图及频率任务周期进度。
- 孩子目标列表、目标详情和虚拟成长。
- 家长首页和两个孩子的管理视图。
- 任务池与目标编辑快照。
- 指定业务日期的清算审阅。
- 当前有效清算和清算修订历史。
- 已达成及已终止目标历史。
- 版本化导出备份快照。

查询不得隐式执行清算、达成目标、迁移或修复数据，也不得返回允许页面直接修改的领域实体。

### 9.4 内部持久化 Seam

家庭习惯 Module 内部保留一个粗粒度持久化 Seam：

- ArkData Adapter 用于正式应用。
- 内存 Adapter 用于电脑本地领域测试。

这是一个真实 Seam，因为存在两个用途明确的 Adapter。ArkUI、文件选择器、动画和音效不通过此 Seam，也不得直接访问数据库。

### 9.5 依赖方向

依赖方向为：ArkUI 和 HarmonyOS 设备 Adapter 依赖家庭习惯 Interface；家庭习惯 Implementation 依赖内部持久化 Interface；ArkData Adapter 和内存 Adapter 实现该内部 Interface。领域规则不得依赖 ArkUI、ArkData、系统时钟、音频或文件选择器。

所有业务日期由调用方显式传入。动画、音效和文件选择失败是领域事务之外的设备失败。

## 十、事务、修订与数据一致性

- 提交打卡、撤销打卡、清算、撤销清算、目标规则变更和数据恢复通过 execute 完成。
- 一次每日清算中的所有目标结果、积分、连续记录、历史最高积分和目标状态共同提交或共同回滚。
- 清算审阅包含当前数据修订号；确认时修订号不匹配则拒绝旧预览。
- 撤销历史清算时，从受影响业务日期开始按日期顺序重算；重算整体完成前不暴露部分结果。
- 进行中目标的规则编辑以保存时的新修订生效，只影响尚未清算的结果。
- 数据库模式和备份格式具有独立、单调递增的版本号。

## 十一、错误与失败处理

### 11.1 领域错误

| 错误类别 | 触发示例 | 用户处理 |
| --- | --- | --- |
| 验证失败 | 空目标、门槛非法、扣分值非法、计划无效 | 保留输入并标出需修正字段 |
| 权限不足 | 孩子尝试清算或管理目标 | 返回孩子可理解的无权操作提示，不改变数据 |
| 家长密码错误 | 解锁家长端失败 | 保持孩子端或锁定状态 |
| 对象不存在 | 任务、目标、打卡或清算已不存在 | 刷新当前视图并提示记录已变化 |
| 目标不可操作 | 已达成或已终止目标收到普通编辑或打卡命令 | 提示目标已结束，不改变历史 |
| 日期已清算 | 尝试直接修改已清算日期 | 引导家长先撤销清算；孩子只能联系家长 |
| 计划不适用 | 对未安排日期提交只适用于按日期任务的操作 | 提示该日期没有此任务要求 |
| 清算预览过期 | 审阅后打卡、豁免或规则发生变化 | 要求重新审阅，不按旧结果入账 |
| 备份无效 | 格式损坏、版本不兼容或不满足不变量 | 拒绝恢复，保留当前数据 |

### 11.2 设备与存储失败

- 任何数据库写入失败都必须回滚当前 execute 命令，并显示中文错误提示。
- 动画或音效失败不得撤销已经确认的清算；结果页面仍显示文字和积分。
- 导出文件选择被取消视为用户取消，不显示数据损坏错误。
- 导出失败不改变业务数据。
- 恢复失败不替换当前数据库。
- 应用异常退出后，重新启动只能看到完整提交的数据。

## 十二、清算反馈表现

- 每个目标独立生成一段老师反馈。
- 奖励项逐项说明，但鼓励动画最多一次。
- 扣分项逐项说明，但惩罚动画最多一次。
- 当日没有奖励时不播放鼓励；没有扣分时不播放惩罚。
- 反馈播放失败或中途退出不影响清算有效性。
- 同一清算自动展示一次；之后可以查看有效清算的静态总结，但不自动重播动画。
- 第一版使用文字、轻量动画和适量短音效，不进行语音朗读。

## 十三、HarmonyOS 兼容性与运行约束

- 使用普通 HarmonyOS 应用、ArkTS、ArkUI Stage 模型和单 Entry HAP。
- 使用 ArkData relationalStore 保存权威业务数据。
- 兼容目标必须覆盖实机 HarmonyOS 6.1.0 对应的 API 版本；工程建立时由 DevEco Studio 连接实机确认 API level。
- 第一版不得依赖高于实机 API level 的必要能力。
- 应用资源随 HAP 安装，核心流程断网可用。
- 第一版适配 MatePad 11.5 横屏、竖屏、分屏、系统安全区和字体变化。
- 操作同时考虑孩子触控准确度；阳阳端优先大触控区域和图形提示。
- 家庭自用阶段通过 DevEco Studio 签名安装；升级必须保持应用标识和签名一致。
- 第一版不使用 ArkWeb、Capacitor、Tauri、快应用或元服务承载核心产品。
- 家长密码不得以明文或可逆形式保存；日志和备份摘要不得暴露密码材料。

## 十四、迁移、备份与恢复

### 14.1 首次安装

- 初始化数据库模式版本。
- 创建两个固定孩子账套和内置任务模板。
- 不预创建带积分的目标、打卡或清算数据。

### 14.2 应用升级

- 每个数据库模式变化都有确定的从旧版本到新版本迁移路径。
- 迁移前创建内部保护副本。
- 迁移在事务中完成，失败则回滚并保留旧数据。
- 发布前必须用上一发布版本的真实结构化样本验证原地升级。
- 不允许通过删除数据库解决发布版本升级问题。

### 14.3 手工备份

- JSON 备份包含全部领域数据、模式版本、备份格式版本、导出时间和完整性校验。
- 备份不包含家长密码、密码派生值、会话状态或设备偏好；恢复后继续使用当前设备的家长密码。
- 家长可以把备份保存到应用沙箱外的用户选择位置。
- 恢复前展示备份摘要，包括导出时间、孩子和记录数量。
- 恢复现有数据前自动创建当前数据保护副本。
- 更高版本且无法安全理解的备份必须拒绝导入。

### 14.4 未来多设备迁移

多设备共享不在第一版范围。未来需要时，保留家庭习惯 Interface 的领域命令语义和稳定实体标识，另行设计身份、权威副本、同步和冲突规则；不得在第一版预建空的同步层。[来源：ADR-0001、ADR-0002、R-002]

## 十五、可观察性与审计

第一版不使用远端遥测或云端监控。可观察性聚焦本机故障排查和家庭结果追溯：

- 开发版记录应用启动、数据库打开、模式迁移、execute 命令类别、事务结果和错误类别。
- 日志不得记录家长明文密码、密码派生值、完整备份内容或孩子的自由文本描述。
- 发布版日志使用最小必要信息，并允许通过 DevEco Studio 或系统日志排查崩溃和数据库失败。
- 每次清算保存版本、业务日期、确认时间、奖扣明细和当前有效状态。
- 撤销及重新清算保存修订关系，不能覆盖旧版本。
- 数据导出、恢复和模式迁移保存本地结果记录及发生时间，但不保存备份正文副本到日志。
- 动画或音效失败单独记录，不改变清算状态。

## 十六、测试策略

### 16.1 测试原则

- 家庭习惯 Interface 是主要测试表面。
- 测试通过 openSession、execute 和 inspect 观察行为，不依赖内部表名、SQL、积分计算函数或页面实现。
- 领域测试使用内存 Adapter，在电脑本地快速运行。
- ArkData Adapter 通过模拟器或真机合约测试验证事务、约束、重启持久化和迁移。
- 页面自动化测试验证孩子打卡和家长清算主流程，不重复穷举领域计分规则。
- 真机验收覆盖 HarmonyOS 6.1、横竖屏、分屏、断网、音效、动画、后台恢复和文件选择器。
- 仓库当前没有既有测试范例；第一批测试将建立家庭习惯 Interface 的行为测试约定，后续测试沿用该表面。

### 16.2 必测领域场景

- 两个孩子账套的数据隔离和界面切换。
- 多目标共享一条打卡记录并按各自规则计分。
- 频率任务同日多次达标、达标后超额和周期结束未达标。
- 日期豁免和周期豁免对连续记录的影响。
- 连续奖励首日、递增、上限、中断和重新起算。
- 同日奖扣合计、零分下限和超额达成。
- 规则快照及进行中规则修改对历史结果的隔离。
- 清算预览过期、事务失败和重复确认保护。
- 撤销早期清算后的后续重算及已达成目标恢复。
- JSON 导出、完整性检查、恢复和版本不兼容。

### 16.3 测试层次

| 层次 | 环境 | 重点 |

| ArkData 合约测试 | HarmonyOS 模拟器与真机 | 事务、持久化、约束、模式迁移 |

## 十七、验收标准

### 17.1 入口、账套与权限

- **AC-01**：首次安装后存在果果和阳阳两个孩子账套，且不能新增或删除孩子。
- **AC-02**：孩子无需密码即可进入孩子端，并能切换果果和阳阳。
- **AC-03**：每个孩子页面持续显示可辨认的昵称、头像或主题，切换后任务和目标数据随之切换。
- **AC-04**：进入家长端必须通过家长密码验证；错误密码不能获得管理或清算权限。
- **AC-05**：孩子尝试管理任务、目标、豁免或清算时被拒绝，已有数据不变。

### 17.2 任务池与目标

- **AC-06**：家长可以从幼儿园或初中模板复制任务到相应孩子任务池，复制后可独立修改。
- **AC-07**：模板后续变化不改变已经复制的任务池任务。
- **AC-08**：被目标引用的任务池任务只能停用，停用后历史引用仍可查看且不能加入新目标。
- **AC-09**：家长不能创建没有目标任务或没有虚拟养成活动的打卡目标。
- **AC-10**：有效目标保存后立即成为进行中目标，并开始按任务计划提供任务。
- **AC-11**：同一孩子可以同时拥有多个目标，各目标积分独立。
- **AC-12**：目标任务创建后保留独立规则快照，修改任务默认配置不改变已有目标任务。

### 17.3 打卡、计划与豁免

- **AC-13**：孩子和家长都可以提交打卡；孩子可以撤销未清算记录。
- **AC-14**：同一任务池任务被多个进行中目标引用时，一条打卡记录被各目标按自身规则解释。
- **AC-15**：按日期任务在未安排日期不产生未完成结果，也不中断连续记录。
- **AC-16**：按日期任务同日存在多条打卡时，在一个目标内最多产生一次完成积分。
- **AC-17**：每周三次的频率任务允许三条打卡都发生在同一天，并在第三条所属日期达到周期要求。
- **AC-18**：频率任务达标前不计分，达标后周期内超额记录不重复计分。
- **AC-19**：频率任务到周日仍未达标时，周日产生一次未完成结果。
- **AC-20**：按日期任务豁免和周期任务豁免均不奖不扣，且不推进或中断连续记录。

### 17.4 积分与连续奖励

- **AC-21**：完成任务按目标任务完成积分计分；未完成按配置不得分或扣一次分。
- **AC-22**：连续奖励第一个完成结果额外为零，第二个为一分，第三个为两分。
- **AC-23**：连续奖励达到目标任务上限后不再增加；未设置上限时继续递增。
- **AC-24**：未完成会中断对应目标任务的连续记录，下一次完成的额外奖励从零开始。
- **AC-25**：同一任务池任务在不同目标中的连续记录相互独立。
- **AC-26**：同一目标当天同时有奖励和扣分时先合计净变化，再更新目标积分。
- **AC-27**：净扣分超过当前积分时目标积分停在零，不产生负积分。
- **AC-28**：目标从九十五分获得十分且门槛为一百分时，最终保留一百零五分并达成。

### 17.5 清算与历史修订

- **AC-29**：孩子不能确认每日清算，家长可以对指定孩子和业务日期发起清算审阅。
- **AC-30**：未打卡且未豁免的当日计划任务在清算审阅中自动显示为未完成。
- **AC-31**：清算审阅后相关打卡、豁免或规则发生变化时，旧审阅不能确认并要求重新审阅。
- **AC-32**：一次每日清算覆盖该孩子当日全部进行中目标，任一写入失败时所有目标均不改变。
- **AC-33**：已清算日期不能直接修改打卡；家长撤销清算后才可修正并重新清算。
- **AC-34**：撤销和重新清算后旧清算仍保留在家长修订历史中，孩子只看到当前有效结果。
- **AC-35**：撤销较早日期清算会按业务日期重算后续积分和连续记录，不留下部分重算状态。
- **AC-36**：重算使已达成目标低于门槛时，该目标恢复为进行中。
- **AC-37**：家长可以补录并清算过去日期，连续奖励按业务日期或周期计算，不按操作时间计算。

### 17.6 目标结束与虚拟反馈

- **AC-38**：目标积分达到门槛或门槛降低到当前积分时，目标立即达成并停止后续计分。
- **AC-39**：计划时长结束但目标未达成时，目标继续进行。
- **AC-40**：家长可以提前终止进行中目标；已达成和已终止目标在目标历史中可区分且不可直接编辑。
- **AC-41**：扣分使当前积分下降时虚拟成长不倒退，只有积分超过历史最高值后继续成长。
- **AC-42**：存在多个奖励项时逐项说明且只播放一次鼓励动画。
- **AC-43**：存在任何扣分项时逐项说明且只播放一次惩罚动画，即使目标净积分为正。
- **AC-44**：同一目标同时有奖励和扣分时，反馈顺序为奖励、扣分、净变化与累计进度。
- **AC-45**：动画或音效播放失败时，清算积分和目标状态保持有效，并显示文字结果。

### 17.7 数据、兼容与恢复

- **AC-46**：关闭应用、设备重启或断网后，已提交的完整业务数据仍可使用。
- **AC-47**：应用在目标 MatePad 的横屏、竖屏和分屏模式下完成孩子打卡与家长清算主流程。
- **AC-48**：家长可以导出包含版本和完整性信息的完整 JSON 备份到所选公共位置。
- **AC-49**：损坏、不兼容或违反领域不变量的备份被拒绝，当前数据保持不变。
- **AC-50**：有效备份恢复后，两个孩子的任务、目标、打卡、清算历史、积分和虚拟成长与导出时一致。
- **AC-51**：从上一发布模式升级失败时旧数据仍可使用，不通过删除数据库完成升级。
- **AC-52**：应用使用稳定签名和应用标识升级后，本地数据原地保留。
- **AC-53**：初中和幼儿园模板分别包含本规格列出的基础学习与生活任务。
- **AC-54**：家长可以分别更换果果和阳阳的内置主题及老师形象，孩子端随之使用新配置。
- **AC-55**：导出的备份不包含家长凭证或会话数据，恢复不会覆盖当前设备的家长密码。

## 十九、完整性审查

### 19.1 模糊和冲突检查

- “积分账户”已统一为孩子账套和各自独立的目标积分，不存在孩子总积分钱包。
- “虚拟目标”与“虚拟任务”已统一为虚拟养成活动。
- “连续完成目标”已统一为目标任务各自的连续记录。
- “计划时长”不是截止期限，目标到期后可以继续。
- 按日期任务和频率任务的完成、未完成归属日已分开定义。
- 频率任务同日多次完成已经明确允许。
- 网页、多设备同步和冲突覆盖规则已被 HarmonyOS 原生单设备决定取代。
- 模块方案已经选择方案一，未保留多个实施分支。

### 19.2 占位与阻塞检查

- 没有未填写的字段占位。
- 没有仍需业务决策的开放问题。
- 完整 MatePad 商品年份或 SKU 未确认，但 HarmonyOS 6.1.0 和实机 API level 验证足以确定工程兼容配置，不阻塞规格批准。
- GitHub Issue #2 是本规格的父工作项，并已标记为 `ready-for-agent`。

### 19.3 规模检查

- 第一版只有一个家庭、一个家长身份和两个固定孩子账套。
- 第一版只有一个家庭习惯 Module 和一个本地数据库，不包含远端系统。
- 动画、音效和内置模板按轻量资源实现，不引入游戏或视频能力。
- 未来多设备、公开发布和跨平台均明确留在本规格之外。

## 二十、批准条件

SPEC-HABIT-001 已获批准，现为第一版实施和验收基线。后续实施计划可以拆分工程骨架、家庭习惯 Interface、领域规则、ArkData Adapter、ArkUI 主流程、虚拟反馈和备份恢复等任务，但不得绕过本规格改变业务不变量或已接受 ADR。

规格内容如需修改，应先更新本文件并保持验收标准与来源追踪一致。
