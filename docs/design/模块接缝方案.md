# 儿童习惯养成模块接缝方案

## 设计前提

- 领域语言以根目录 `CONTEXT.md` 为准。
- 已确认第一版采用 HarmonyOS 原生、本地优先、单设备运行，但模块内核不依赖 ArkUI 或 ArkData。
- 孩子打卡与家长清算是最高频流程。
- 每日清算、撤销清算和历史重算必须保持原子性。
- 领域规则需要通过电脑本地测试，不应要求每次启动模拟器或真机。
- 第一版不承担服务器、账号系统、多设备同步和冲突合并成本。

复杂度主要集中在四件事：同一打卡记录被多个目标任务解释、日期计划与频率计划并存、连续奖励和目标状态随清算变化、撤销历史清算后向后重算。好的 Module 应用小 Interface 隐藏这些行为，让页面不必了解计算顺序或持久化结构。

## 方案一：单一家庭习惯 Module

### 形态

```text
ArkUI 与设备能力
        ↓
家庭习惯 Module
        ↓ 内部持久化 Seam
ArkData Adapter / 内存 Adapter
```

家庭习惯 Module 同时处理会话、权限、孩子账套、任务、目标、打卡、清算、反馈语义和备份格式。

### 公共 Interface

```text
openSession(入口与凭证) -> 会话
execute(会话, 领域命令, 预期修订号?) -> 命令结果
inspect(会话, 查询请求) -> 只读快照
```

命令使用“提交打卡”“确认每日清算”“撤销每日清算”等业务意图，不提供表级增删改。查询返回孩子今日、目标进度、清算审阅和历史等场景快照，不返回可变领域实体。

### 数据所有权与依赖方向

- 家庭习惯 Module 独占全部领域数据的写入权。
- ArkUI 只持有表单草稿、会话和只读快照。
- 持久化 Interface 是 Module 的内部 Seam，ArkData Adapter 和内存 Adapter 分别用于正式运行和本地测试。
- 动画、音频和文件选择器依赖家庭习惯 Interface，不参与领域事务。

### 测试 Seam

家庭习惯 Interface 是主要测试表面。测试使用内存 Adapter 执行命令并读取快照；另用少量 ArkData Adapter 合约测试验证事务、升级和重启持久化。

### 失败隔离

- 持久化失败会回滚整个命令。
- 动画或文件保存失败不影响已经确认的清算。
- 由于权限、备份和清算都在一个 Module 中，内部错误影响面较大。

### 迁移成本

- 更换本地持久化：低。
- 调整页面：低。
- 将身份、反馈或备份交给其他实现：中等，需要从大 Module 中提取职责。
- 增加网页或多设备：中高，Interface 语义可保留，但实现和调用方式需要扩展。

### 评价

该方案的方法数量最少，调用者获得较高 Leverage；但命令、查询、错误和权限规则会持续扩大 Interface。它的 Depth 容易被“所有东西都塞入一个入口”伪装，长期 Locality 未必理想。

## 方案二：深账本与失败影响隔离

### 形态

```text
ArkUI
├── 家庭会话 Module
├── 习惯账本 Module
├── 反馈演出 Module
└── 数据搬迁 Module

习惯账本 Module
        ↓ 内部持久化 Seam
ArkData Adapter / 内存 Adapter
```

习惯账本 Module 独占所有需要共同清算和重算的领域数据。家庭会话、反馈演出和数据搬迁按照不同失败影响独立。

### 公共 Interface

**家庭会话 Interface**

```text
enterChild(孩子标识) -> 孩子授权
unlockParent(密码) -> 家长授权
lockParent() -> 已锁定
```

**习惯账本 Interface**

```text
loadDay(授权, 孩子, 业务日期) -> 当日视图
previewSettlement(家长授权, 孩子, 业务日期, 修正?) -> 清算预览
execute(授权, 领域命令, 预期修订号?) -> 领域结果或清算回执
```

清算预览带不透明的预览凭据。确认时如果相关打卡、豁免或规则已经变化，账本拒绝旧预览，要求重新审阅。

**反馈演出 Interface**

```text
compose(清算回执, 孩子展示资料) -> 可重放反馈序列
```

反馈序列只描述老师说明、鼓励、惩罚、积分和成长进度的顺序；ArkUI Adapter 决定具体动画和音效。

**数据搬迁 Interface**

```text
export() -> 版本化备份
inspect(备份) -> 检查结果
restore(备份, 恢复确认) -> 恢复结果
```

### 数据所有权与依赖方向

- 习惯账本拥有孩子账套、任务池任务、目标任务、打卡记录、豁免、任务结果、清算、积分、连续记录和目标状态。
- 家庭会话只拥有家长密码摘要和短期授权状态。
- 反馈演出只拥有反馈模板和可重放状态，不拥有积分。
- 数据搬迁拥有备份格式和迁移规则，通过账本的内部快照 Seam 搬运完整数据，不逐表修改领域状态。
- 领域依赖方向始终指向习惯账本；习惯账本不依赖 ArkUI、动画、音频或文件选择器。

### 测试 Seam

- 通过习惯账本 Interface 测试完整行为，不直接测试内部积分计算器或计划展开器。
- 通过内存 Adapter 测试清算、撤销和重算；通过 ArkData Adapter 合约测试验证持久化语义一致。
- 反馈演出是输入清算回执、输出反馈序列的纯测试 Seam。
- 页面测试只验证调用正确 Interface，不重复验证积分规则。

### 失败隔离

- 清算中任何目标失败，整次每日清算都不生效。
- 清算成功后动画或音效失败，账本结果仍有效，并可重新播放反馈。
- 导出失败不改变账本；恢复先检查，再以完整事务替换，失败时保留原数据。
- 密码验证失败不会进入账本的家长命令。

### 迁移成本

- 更换 ArkUI 或调整反馈风格：低。
- 更换本地持久化：低至中。
- 修改备份版本：集中在数据搬迁 Module，成本中等。
- 增加网页只读入口：中等。
- 增加多设备写入与同步：中高，需要新增真正的远端 Seam。

### 评价

习惯账本用一个 Interface 隐藏最复杂的强一致性行为，具有高 Depth 和 Leverage。不同失败影响集中在对应 Module，Locality 最好。代价是 ArkUI 会认识四个 Module，但每个 Interface 都与一个清晰用户流程对应。

## 方案三：为未来远端入口准备的领域内核

### 形态

```text
ArkUI Adapter ─────────────┐
未来 HTTP Adapter ────────┼─> 家庭习惯内核 Module
导入导出 Adapter ─────────┘          ↓
                              持久化 Port
                         ArkData / 内存 Adapter

家庭访问门禁 -> 会话授权 -> 家庭习惯内核
家庭习惯内核 -> 清算回执 -> 亲子反馈
```

家庭习惯内核仍独占领域数据，但从第一版起为命令幂等、修订控制和跨运行时场景夹具保留信息，以降低未来增加网页和同步的迁移成本。

### 公共 Interface

```text
execute(带稳定命令标识的命令, 预期修订号?) -> 命令结果
query(用途明确的查询) -> 只读结果
transfer(导入导出请求) -> 搬迁结果
```

每条命令具有稳定命令标识，每个实体具有稳定标识和修订号。未来进程内 Adapter 可以替换为 HTTP Adapter，调用语义保持一致。

### 数据所有权与依赖方向

- 家庭习惯内核拥有全部权威领域数据。
- ArkUI 与未来 HTTP Adapter 都只能通过同一 Interface 提交意图。
- 第一版只存在 ArkData 和内存两个持久化 Adapter，不创建同步 Adapter、服务器或冲突合并逻辑。
- 亲子反馈和访问门禁不拥有账本数据。

### 测试 Seam

- 本地测试通过内存 Adapter 执行带标识的命令序列。
- JSON 场景夹具描述命令和预期结果，可供未来 ArkTS、网页或服务器实现运行同一组行为验证。
- 未来 HTTP Adapter 复用家庭习惯内核 Interface 的合约测试。

### 失败隔离

- 命令幂等可避免重复点击或未来网络重试导致重复计分。
- 预期修订号阻止旧页面覆盖新状态。
- 未来网络故障不会阻止本地内核工作，但真正的同步冲突仍需届时决定。

### 迁移成本

- 第一版实现和数据字段成本高于方案二。
- 增加只读网页入口：低至中。
- 增加远端写入：中等，但仍需身份、传输和冲突策略。
- 增加多设备同步：中高；稳定标识与命令幂等只能降低部分成本，不能消除业务决策。

### 评价

该方案对未来调用者提供最高 Leverage，但其中一些 Seam 在第一版只有假设中的第二个 Adapter。它会把尚未发生的联网需求带入本地模型，违反“一个 Adapter 只是一个假设 Seam”的原则，第一版的 Depth 会被预留字段和协议复杂度稀释。

## 横向比较

| 维度 | 方案一：单一家庭习惯 | 方案二：深账本与隔离 | 方案三：未来远端内核 |
| --- | --- | --- | --- |
| 公共 Interface | 3 个统一入口，类型集合较大 | 4 个用途清晰的 Interface | 3 个传输友好入口 |
| 数据所有权 | 全部集中在一个 Module | 强一致性数据集中在账本，其他数据按失败影响分离 | 全部集中在领域内核 |
| 依赖方向 | 简单，但内部职责多 | 清晰，设备能力均在外侧 | 清晰，但带未来传输约束 |
| 测试 Seam | 单一测试表面 | 账本为主，反馈和搬迁可独立验证 | 适合跨运行时合约测试 |
| 失败隔离 | 中等 | **最好** | 较好 |
| 第一版成本 | 最低 | **低** | 最高 |
| 更换 UI 成本 | 低 | **低** | 低 |
| 增加多设备成本 | 高 | 中高 | **中高但准备较充分** |
| Interface 膨胀风险 | 高 | **低至中** | 中 |
| Locality | 中 | **高** | 高 |

## 已选方案

用户选择**方案一：单一家庭习惯 Module**，以降低第一版的 Module 数量和调用复杂度。家庭习惯 Module 通过 `openSession`、`execute`、`inspect` 三个入口统一承载会话、权限、任务、目标、打卡、清算、反馈语义和备份规则；持久化仍是它的内部 Seam。

已选方案的核心决定是：

> 家庭习惯 Module 独占全部领域数据和领域行为，ArkUI 只能通过三个公共入口提交意图或读取快照；每日清算、撤销和重算由该 Module 在一个事务内完成。

相比原推荐的方案二，这一选择减少了公开 Module 和 Interface，也接受家庭习惯 Module 内部职责较多、命令与查询类型可能逐渐扩大的代价。后续只有在身份、反馈或备份出现第二种真实 Adapter，或者 Interface 明显失去 Depth 时，才提取新的外部 Seam。

HarmonyOS 原生、本地优先与网页方案之间同样是高代价技术选择，已经单独记录为 ADR，避免把平台选择和领域 Module 接缝混成一项决定。

## 已批准的设计基线

1. ArkUI 不直接读取或修改领域数据库，只调用家庭习惯 Interface。
2. 只有家庭习惯 Module 能改变目标积分、连续记录或目标状态。
3. `inspect` 清算审阅不产生领域变化；确认清算通过 `execute` 提交，并携带对应修订信息。
4. 一次每日清算覆盖该孩子当日全部进行中目标，要么全部成功，要么全部失败。
5. 动画、音效或文件保存失败不撤销已经确认的清算。
6. 数据恢复先检查完整备份，再由家庭习惯 Module 原子替换现有数据。
7. 电脑本地测试与正式应用通过同一个家庭习惯 Interface，分别使用内存和 ArkData Adapter。
8. 第一版不为假设中的远端身份、网页入口或多设备同步建立外部 Seam。
