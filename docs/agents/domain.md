# 领域文档

## 布局和读取顺序

本仓库采用单上下文布局：

- `CONTEXT.md`：根目录中的领域概念和术语表。
- `docs/adr/`：架构决策记录。

探索代码前，先读取 `CONTEXT.md`，
再读取与当前工作相关的架构决策记录。

如果以后出现根目录 `CONTEXT-MAP.md`，
先读取该索引，再读取相关上下文的 `CONTEXT.md`、
上下文内的 `docs/adr/` 和根目录的相关决策记录。

这些文件尚不存在时，直接继续工作，无须报告缺失或提前创建。
领域术语或架构决策明确后，由 `domain-modeling` 技能按需建立。

## 使用领域术语

事项标题、重构建议、假设和测试名称中的领域概念，
统一使用 `CONTEXT.md` 定义的术语。

所需概念尚未收录时，先判断是否符合项目现有语言；
确有缺口时，记录下来供 `domain-modeling` 补充。

## 显式说明决策冲突

建议与已有架构决策冲突时，指出对应 ADR，
说明冲突内容及重新讨论该决策的理由。
